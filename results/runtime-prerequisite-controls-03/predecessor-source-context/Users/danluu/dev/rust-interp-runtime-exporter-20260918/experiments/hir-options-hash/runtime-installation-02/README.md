# Runtime installer reconciliation successor

This is an unrun source proposal. It adopts the separately passed native
reconciliation receipt as the native qualification owner. The original failed
native03 commands remain in their original namespace and are checked by the
actual hash stage's `Stage.prerequisites()` reader. Both actual native and hash
audits must exist before runtime discovery can begin.

The new `prerequisites.Reader` retains every original hash file, link and absence
in the full runtime union. Its private reader state uses the original hash
`snapshot_inputs` when binding that historical v2 projection; it neither replaces
the enclosing runtime selection nor mutates either supplied freeze. The exact
hash `snapshot_bindings.py` module must be present. No snapshot helper is imported
or invoked by the Reader or factory. The independently qualified hash snapshot
receipt, manifest and projection remain required evidence.

`imports.py` uses a separate private alias prefix and checks the binding source
before and after loading the hash definition graph. It continues to load
`recipe.py`, `discovery.py`, `controller.py` and `monitor.py` from the original
`runtime-installation-01` directory. Their exact original paths and bytes retain
the existing 21-control qualification; the new adapter is not relabeled as having
passed those controls. All 16 original source files, including their existing
source-binding catalog and tests, are preserved and will be frozen by preparation.

The only outer recipe changes are the native qualification evidence route and
fresh R `hir-options-hash-runtime-{preflight,installation}-02` evidence and
supervisor names. The production R installer, source capability, two source
preflight probes, final probe recipe, provider roles, allocation adapter and
24/9/8, 14 GiB namespace and 256 MiB aggregate evidence bounds are unchanged.
`frozen.py` and `preflight_history.py` are exact source copies of the reviewed
original. Local packet names remain `preflight-plan-01` and
`installation-plan-01` beneath this distinct successor directory.

`test_prerequisite_successor.py` contains focused in-memory Reader and factory
controls. They cover the separate failed command owner and passed qualifier,
missing/foreign audits, preservation of both logical selections, exact binding
module route, rejection from the saved command reader, and reuse of original
installer source paths. No control has been executed. The original 21 controls
remain separate and unchanged.

The runtime's own eventual proof retention still uses the qualified helper with
its existing full source selection and reservation. This change adds no reuse
credit to that new stage, changes no cap and makes no claim that its future
aggregate reservation will fit. The actual four-prerequisite discovery and
snapshot measurement remain necessary after source/control review.
