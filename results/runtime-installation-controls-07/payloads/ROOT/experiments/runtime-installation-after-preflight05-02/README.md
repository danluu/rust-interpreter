# Installation06 resource successor — source only

This unrun successor prepares and installs the already qualified component bytes
after the exact preflight05 owner receives an independent passed audit. It uses
fresh installation06 packet, preparation, controller, supervisor, launcher and
report routes. The immutable installation05 proposal and its actual 25 controls
remain evidence for the original 24 GiB policy.

The new entry policy is 16 GiB, retaining the 9 GiB stop and 8 GiB floor, 256 MiB
combined evidence limit and 14 GiB combined compiler/prefix namespace limit.
The planning budget is 8 GiB floor + 1 GiB stop cushion + 1 GiB installed prefix
+ 0.25 GiB complete evidence + 4 GiB unmeasured RSS/swap allowance = 14.25 GiB,
rounded to 16 GiB. It is not derived from current free disk. No compiler or std
rebuild occurs: the admitted composition has 3,708 files / 636,631,680 logical
bytes, and the unchanged recipe has ten loader checks, three compiler information
commands and two expected-E0080 source probes.

`controller.copy_budget` is pure and runs after the unchanged identity/component
validation. It requires exact component snapshot membership, typed bounded
stat/size fields, complete destination identity and ten loader declarations. It
accounts for rounded file payloads, created directories, the exact encoded
admission record, a conservative ready-record template and the existing 32 MiB
qualification receipt bound. The ready template follows the actual writer's
fields, admitted probe values, six-field installed tree stamps and seven-field
qualification stamp, using 21-character signed stat integers. A 64 MiB
failure/filesystem reserve and an atomic temporary reserve cover the remaining
known metadata writers. `workflow_io.write_json` writes one same-directory
temporary at a time. The complete reservation must fit 1 GiB.

Preparation computes this reservation before creating its packet. The controller
reconstructs it before WORK creation, records it in the terminal and repeats the
check at full guards. The private monitor adds the installed-prefix allocation
to its existing sample and rejects a prefix exceeding 1 GiB. The original
installer, recipe, source qualification, providers, factory, Reader, lock helper
and process monitor source files are unchanged. The existing per-MiB capacity
callbacks and full snapshot evidence projection/reservation remain required.

Allocation rounding is a planning estimate, not an APFS guarantee. The prefix
and evidence allocation checks are sampled; output files have no new
RLIMIT_FSIZE. The failure reserve is not a hard bound on arbitrary exception
text. RSS/swap and internal compiler concurrency are unmeasured. No disk space
is reserved against unrelated work, which must never be interrupted.

The inherited 25 test methods are revised for installation16, with meaningful
subtests covering stale24 rejection, exact budget boundary/overflow, malformed
sizes/stamps, missing snapshot membership, changed identity/loader/prefix,
prefix rejection and detached returned policy. These use in-memory census
fixtures and do not claim provider or compiler qualification. One bounded
direct run passed all 25 methods and resource subtests. Its raw output, source
identities and independent readback are retained in
`results/runtime-installation06-test-development-01`. Controlled qualification
and the installation itself remain unrun.

Future control proof paths use `runtime-installation-controls-07`: the earlier
unrun controls06 source directory already exists as preserved history. All new
actual control, preparation, runtime and audit digests remain unset. The source
preflight audit remains an explicit required external digest. Historical
52/39/33 and original25 results are not relabeled as new-source qualification.

The future saved-audit integration must authenticate this controller source and
provide the required `validate_installation_resources(plan)` callback to
`audit_owner.owner`. It must reconstruct `copy_budget` from the authenticated
specification plus the actual installed `admission.json` identity/snapshots and
exact keyed prefix, returning the complete summary. The owner compares that
summary with both plan and terminal. A boolean success marker is insufficient.
Startup-only owner admission retains its existing API. The saved installation
validator still checks the complete ready/qualification schema and loader+5
recipe. No binder, control packet, installation packet or invocation is created
by this source proposal.
