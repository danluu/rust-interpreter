This is an unrun source draft for optimizing host build dependencies at Cargo opt-level 3. All original R scripts, held options-hash screen sources, compiler sources, installed tools, and project sources remain unchanged. The ten pure tests passed once under the root-owned process recorded in `results/host-build-opt-pure-tests-01` (parent 13994, child 15413, normal exit 0). No fixture build, benchmark, or provider command has run for this draft. Future compiler-effect and performance results are unset.

The saved edited baseline self-profile records 2,396 `expand_proc_macro` calls taking 0.546403 seconds, within 1.285550 seconds inclusive `expand_crate` time. Its total is 3.376633583 seconds; inclusive query times overlap. A separate five-edit diagnostic records a 2.318238-second median exporter frontend. These observations establish a material area to investigate, not an exact decomposition of that median or a new performance claim. The derive outer parser's self time is only 0.015915 seconds, so optimizing that conversion alone is unlikely to supply a major reduction.

`evidence.json` binds all 23 actual proc-macro compilations from the corresponding prime history. Every one lacks both `-C opt-level` and `-O`, therefore uses rustc's recorded default 0. Two Cargo crate-type queries are excluded. The host copies of syn, quote, proc_macro2 and unicode_ident are also unoptimized. The three direct dylibs in the selected edited ruff_linter command—ruff_macros, is_macro and strum_macros—match those exact prime output directories and helper dependency routes. The target unicode_ident command separately uses opt-level 1. Individual prime Cargo commands closed successfully, but their enclosing older profiling attempt later failed a profile-output bound; that failure remains explicit. Its approximately 48-second baseline prime Cargo interval is diagnostic setup evidence, not a forecast of the new candidate's cold cost.

The proposed single change is host build-override opt-level 3, selected prospectively before any candidate timing. Level 2 is not another tuning attempt. Cargo supports this override for proc macros, build scripts and their dependencies; other profile fields retain their inherited values, and named package overrides have precedence. Test inherits dev. Higher optimization may increase cold compilation cost. See the [Cargo profile rules](https://doc.rust-lang.org/cargo/reference/profiles.html#build-dependencies) and [configuration transport](https://doc.rust-lang.org/cargo/reference/config.html#profilenamebuild-override). Actual captured argv must confirm the pinned Cargo's behavior, including unchanged target optimization, debug assertions, overflow checks, debug information and codegen policy.

The source draft copies the ordinary runner, verifier, runtime-arm selector and placement helper. Original copies and exact diffs are adjacent. `host_build_profiles.py` adds explicit native/baseline/candidate settings, retaining the existing global option as a fallback. Per-mode values take precedence. With no option, the original namespace and profile behavior are retained. Ambient `CARGO_PROFILE_*` variables are removed, then only declared DEV/TEST build-override opt-level variables are added. Native's ordinary repository profile helper preserves these values; interpreter.py and the runtime environment preserve them into Cargo. No target `RUSTFLAGS` or Cargo target opt-level is introduced. The old selector's blanket rejection of host overrides is removed; runtime/std/tool identity validation remains.

Every configured custom cache namespace contains the host level; native/check target directories contain it too. Actual passed host settings enter command receipts, records, summary, per-mode settings, A/A equality and saved verification. The helper never reads providers or runs commands. The placement copy explicitly retains R as provider owner while selecting draft sources here; source freezing accepts these exact absolute draft paths alongside R-relative script paths.

The prospective AB uses the same original installed tool/runtime/std and HIR-off guest flags in both custom arms, with host 0 versus host 3. AA uses host 0 versus host 0 in two fresh caches. Native's host level must be an explicit fixed protocol choice across both histories; using 3 gives a matching optimized-host native control while retaining its original target profile. No claim about a fastest native configuration follows. The existing five edits, wrong edit, restoration, tests, diagnostics and identical executed RBC requirements remain. The advance criterion remains median of five candidate/baseline complete-command ratios plus median absolute AA ratio deviation below 1. Cold, wrong-edit, restoration, setup and complete session costs stay visible outside that criterion. No future protocol, workload route, tool key or actual result is silently bound by this draft.

The main uncertainty is how much of the 0.546403 seconds is optimized macro/dependency code versus bridge/server work. It includes client invocation rather than exclusively user macro instructions. Eliminating this entire component would still not establish the 0.5-second frontend target. The ordinary same-thread bridge calls an already loaded dylib in process; nested expansion can use a thread. It does not create one compiler process per macro. Saved profiles do not isolate one-time dylib loader cost.

Incremental macro-result reuse is not proposed. Rustc labels the existing `cache_proc_macros` flag potentially unsound. Its derive query keys include token/expansion identity and proc-macro crate hash, but arbitrary filesystem/environment effects remain possible. The dep-graph side-effect journal covers diagnostics and feature uses, not all resolver, hygiene, tracked/untracked I/O and nested expansion effects. The HIR body journal operates after expansion and is not a complete macro effect journal. Host optimization preserves ordinary invocation and all these effects.

`test_host_build_profiles.py` contains ten passed pure regressions covering default/global compatibility, explicit precedence, ambient contamination, cache separation, strict types, duplicate CLI options, mismatched actual call fields, A/A mismatch, the actual ordinary native environment function and runtime identity preservation. These are source tests, not compiler-effect evidence.

The dependency-free `fixture/` is also unrun. Future admission should copy it into an owned temporary source route, obtain its ordinary lockfile, and use the existing compiler-argv recorder and normal Cargo/launcher supervision to compile and test it in fresh host-0 and host-3 caches, keeping explicit target selection equal. The proc macro emits its real `cfg(debug_assertions)` value; the ordinary test requires both host and target checks to remain enabled. Captured host argv must change effective opt-level 0 to 3, while target effective opt-level remains 1 and debug/overflow checks remain enabled. Required counterexamples are a dropped Cargo override, a target-opt-level override, disabled host checks, omitted/duplicated invocation and shared cache route. Merely passing the pure tests cannot qualify this real compiler seam. After that succeeds, apply the same saved-argv check to actual Ruff host dependencies before any timing interpretation. No separate controlled-proof framework is introduced.

The existing O1 proc-macro and host-library wrapper policies have saved correctness qualifications, summarized in `existing-feature-review.json`. They leave Cargo profiles and build-script `OPT_LEVEL`/`DEBUG` unchanged and are incompatible with the selected custom runtime route. This proposal leaves those wrapper policies off. Cargo build-override 3 covers a different set of host units and can change profile-derived build-script inputs; a build script may inspect them and generate different output. The new fixture qualification therefore records both host-dependency and target build-script values, along with actual compiler arguments and test results. It does not assume semantic equivalence from the option name.
