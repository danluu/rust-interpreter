# Oxc target source review

Oxc's `oxc_linter` is a credible additional large-crate development candidate with a cleaner declared dependency route than the observed Nushell test workflow. This is a source review at `4d5c812d6b16c23fa71d106cf87f7f20ddee69b1`, not a benchmark or interpreter qualification. No checkout, Cargo command, test, compiler or sealed holdout was used.

The review followed the linter's normal and development dependencies, then every reachable local normal/build dependency, including all target and optional declarations. It resolved workspace inheritance and the root's allocator patch. The resulting 23 workspace manifests contain 231 dependency declarations, no build-dependency declaration and no path back to `oxc_linter`. The linter's development dependencies are registry `insta` and `markdown`; both reachable local proc-macro crates depend only on registry utilities. These findings support avoiding Nushell's specific edited-crate host back-edge. They do not prove a resolved Cargo unit graph, eliminate registry build scripts, or prove that macros never inspect additional files. [Workspace manifest](https://github.com/oxc-project/oxc/blob/4d5c812d6b16c23fa71d106cf87f7f20ddee69b1/Cargo.toml), [linter manifest](https://github.com/oxc-project/oxc/blob/4d5c812d6b16c23fa71d106cf87f7f20ddee69b1/crates/oxc_linter/Cargo.toml).

The same crate declares 870 leaf rule modules. This counts declarations, not executed tests or total lines of code. The ordinary [`no_debugger`](https://github.com/oxc-project/oxc/blob/4d5c812d6b16c23fa71d106cf87f7f20ddee69b1/crates/oxc_linter/src/rules/eslint/no_debugger.rs) and [`eqeqeq`](https://github.com/oxc-project/oxc/blob/4d5c812d6b16c23fa71d106cf87f7f20ddee69b1/crates/oxc_linter/src/rules/eslint/eqeqeq.rs) tests retain real pass/fail/fix cases and committed diagnostic snapshots. [Rule registrations](https://github.com/oxc-project/oxc/blob/4d5c812d6b16c23fa71d106cf87f7f20ddee69b1/crates/oxc_linter/src/rules.rs).

Those ordinary rule tests require threading. `Tester` constructs `LintService`; `Runtime::new` initializes Rayon's global pool and `run_test_source` enters `rayon::scope` with synchronized state. The route also uses a channel, current-directory lookup, snapshot files and possible real fixture reads. The two inspected ESLint tests do not install external-linter callbacks and leave cross-module import disabled, but that is not proof of the full transitive native ABI closure. Threading, TLS, allocation, filesystem and snapshot behavior need actual interpreter qualification. No thread setting or test was changed to bypass them. [Tester](https://github.com/oxc-project/oxc/blob/4d5c812d6b16c23fa71d106cf87f7f20ddee69b1/crates/oxc_linter/src/tester.rs), [runtime](https://github.com/oxc-project/oxc/blob/4d5c812d6b16c23fa71d106cf87f7f20ddee69b1/crates/oxc_linter/src/service/runtime.rs).

There is a narrower credible workflow within the same large crate: production configuration-name edits exercised by these unchanged existing tests:

- `config::plugins::tests::test_plugin_normalization`
- `config::plugins::tests::test_normalize_plugin_name`
- `config::plugins::tests::test_is_normal_plugin_name`
- `config::rules::test::test_normalize_rule_name`

Their inspected call paths perform string/Cow normalization, plugin alias conversion and assertions; they do not construct `Tester`/`LintService`, enter Rayon, or use snapshot files. They meaningfully cover the corresponding production configuration functions. They do not establish rule-body semantic coverage or a passing interpreter route; libtest, std/native ABI and exporter reachability still require validation. [Plugin functions/tests](https://github.com/oxc-project/oxc/blob/4d5c812d6b16c23fa71d106cf87f7f20ddee69b1/crates/oxc_linter/src/config/plugins.rs), [rule-name functions/tests](https://github.com/oxc-project/oxc/blob/4d5c812d6b16c23fa71d106cf87f7f20ddee69b1/crates/oxc_linter/src/config/rules.rs).

Keep Ruff as the immediately measured development target. Oxc merits a separately budgeted pinned native baseline and unchanged-test compatibility check, initially distinguishing the configuration workflow from threaded rule tests. Preserve the upstream profiles/configuration and record the actual compiler: the pinned toolchain selects 1.98.1. Before performance work, retain the resolved unit graph, actual edited-state rebuild list, complete diagnostics and test identities. There is no Oxc speedup or sub-0.5-second result here.

`source-review.json` records the traversal, exact test paths, limitations and SHA-256/size/raw-Git URL for every fetched source. These are source observations only; no new test result is asserted.
