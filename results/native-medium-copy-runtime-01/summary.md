# Native medium copies: real-artifact runtime screen

The candidate extends the custom AArch64 emitter’s native Copy limit from 32 to 128 bytes. All seven retained real-program artifacts return the same result and execute the same number of guest instructions with unchanged peak guest memory. The screen uses six alternating prior/current pairs per artifact in fresh processes. Every observation is retained.

The complete eighteen-test folded-trie artifact reduces native entries from 87,967,634 to 75,760,367, while generated code grows from 4,813,356 to 5,087,032 bytes. It wins five of six pairs, with a 157 ms median paired reduction. All four word64 variants win six of six pairs. SHA-1 without leaf inlining loses all six by a 4 ms median paired difference; its inlined variant is nearly unchanged. These mixed results are retained, including the first folded-trie loss and a slow prior-build observation.

The 96 bytecode tests include every new length, all sixteen alignments, both overlap directions, stack/heap combinations, complete memory comparison, invalid-range rejection without writes, full-width live values, exact budgets, and larger-copy fallback. Vector registers v0 through v7 hold complete source chunks before any destination write; the existing whole-range checks and scalar tail handling remain in force. Instruction encodings were independently checked against the Arm reference and local assembler output.

These command times include VM startup, bytecode loading, JIT construction and execution. They exclude Cargo, checking and export, so they are a direction screen rather than proof of faster development commands. Broad native differentials and complete production-edit comparisons remain required. CPU-query build59 is the experimental baseline; previously selected build07 remains selected.
