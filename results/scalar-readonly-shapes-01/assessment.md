# Read-only body census: limited local reuse opportunity

All 199 saved profiled scalar bodies reconstruct byte-for-byte from their
original artifacts and the candidate emitter. One address-identity control and
one observer command pass. There is no new guest execution or executable code
publication. Closure binds 253 frozen sources and retained inputs.

The 30 new block-test bodies account for 7,727,363 successful Calls. They perform
13,846,141 external reads, 25,543,166 binary computations, 11,128,514 packs and
11,275,184 casts on those successful paths. Same-block duplicate read identities
account for 974,848 visits, all in `encoded_pattern_len`; common address families
account for 1,042,496 visits after each family's first read. These counts overlap.
The corresponding exhaustive-test duplicate count is only 1,814; folded has none.

The two `look_have` / `look_need` bodies dominate the new Calls (4,036,480
combined) and have no duplicate read identities. Same-width casts remain common,
but counts alone do not show that their machine work survives existing
register/dead-code optimization. Body sizes include profiling instrumentation.
Private failed attempts are absent from successful-Call counters. These results
do not establish a timing cause or justify another read-reuse-only candidate.

Keep the failed candidate parked. Next compare bounded nested-Call and wider
result opportunities against current adopted-VM samples before expanding the
scalar ABI or value model. Static shape acceptance is only an upper bound;
effects, aliasing, budgets, native emission and original-test behavior still need
proof. Preserve the earlier tree and wider-memory failures when selecting work.
