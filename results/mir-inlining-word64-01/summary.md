# MIR inlining: original word64 tests after production edits

Twelve original word64 tests after five cumulative production edits. Performance evidence applies to this workflow. Expanded native differential checks now pass for all three explicit configurations; broader production configuration comparisons remain pending.

The pinned default MIR inlining thresholds are 50 general, 100 with an inline hint, and 30 for forwarders. These experiments multiply all three while retaining MIR level 3, frontend checking, and development overflow checks. Native uses its unchanged Cargo test profile. Engine defaults remain unchanged.

Each runtime comparison uses alternating processes, the same VM binary, and bytecode exported from identical final production source. Both sides run the original test inputs and assertions. Artifact load and JIT compilation are included. Profiling runs are separate and are not performance samples.

Complete command times include Cargo, checking, export, launch, and execution after real source changes. Cold commands use empty per-mode build caches but exclude compiler/runtime bootstrap and OS cache coldness. Separate runs have different native timings; full-command differences are not isolated causal estimates. All raw samples, flags, hashes, phase medians, and instruction/memory counts are retained in the JSON.

Custom Cargo RUSTFLAGS can also affect host tools when Cargo has no explicit target. The experiment does not claim a gain for whole applications or other projects.

The expanded native differential/rejection run passed 21,927 commands on the subsequent host-wrapper candidate, including all three threshold configurations. [Validation record](../jit-entry-alwaysinline-validation-01.json).
