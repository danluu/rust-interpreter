# Guarded runtime qualification, completed with an offline validator repair

The custom VM passes478 workspace Rust tests per debug/release profile, one
ignored, and143 harness checks with ten separately qualified opt-in skips.
Seven selected tests, nine suites and203 strict native/cache commands pass.
All three profiled guest processes also succeed. No guest was rerun.

The first profile validator incorrectly demanded positive guard activity in
every workload. Both token profiles passed; folded reached that assertion with
no active group under the eight-access/audited-opcode threshold. Preserve that
failure. The repaired validator requires active guards for both token profiles,
and accepts an inactive folded control only with zero cache reloads and exact
adopted generated bytes. All three saved profiles were rechecked offline against
unchanged original inputs and an archived copy of the original driver.

Every per-PC count and native interval, JIT entry count, memory/entropy total and
same-process operation-map reconstruction matches. Speculative branches stay
within preflight or target the unchanged-entry fallback; cached addresses stay
inside their guarded regions. The folded code hash is identical to adopted.
Counts and byte reductions are not timing results. The frozen changed-source
screen and every full adoption guard remain required before runtime adoption.
