# Installation after preflight05: source proposal

This is an unrun installation-only successor. It consumes the exact preflight05 descriptor and requires an independently verified, completed preflight05 audit supplied by an external SHA-256 pin. No completed preflight or installation is asserted by these source files. The old preflight05 source, its actual33 controls, and qualified runtime04/startup39 sources remain unchanged.

The six scripts and descriptor have precise adjacent `*.from-preflight05.diff` files. `entry.py` keeps the original qualified factory, Reader, recipe, discovery, monitor, file-table reconstruction, completed-catalog validation and physical snapshot readback. It selects a distinct installation controller and retains the canonical descriptor through full validation, construction and execution. Installation admission stays 24 GiB, with the same 9 GiB stop, 8 GiB floor, 14 GiB combined allocation cap and 256 MiB evidence cap.

`prepare.py` inherits the compact preflight05 table and the actual packet, work, supervisor, launcher and preparation evidence. Its explicit prerequisite validation calls the unchanged path-parameterized `preflight_history.validate`. The installed key derives from the existing recipe and the actual preflight result/policy references. The exact command count is `len(specification['loader']) + 5`: loader inspection, three compiler identity/options commands, and two local/virtual source diagnostic probes. The old specification has ten loaders, but this proposal does not hardcode a future fifteen-command result.

The current seven sources require a separate future installation control proof. Old52, old39 and actual33 retain their own source associations. `test_installation.py` contains 25 pure controls (seven route, seven phase/qualification, eleven prerequisite cases). Its mocked history callback checks dispatch and refusal propagation; it does not model the real two compiler probes or claim their qualification. No test has been imported or run. The unchanged inherited-FD helper and process-observation bodies remain covered only by their original evidence until a concrete new source packet is qualified.

`qualification-plan.json` lists the exact direct fixture dependencies and existing actual33 harness to derive. The future control source/work/audit routes are reserved only as strings; no control packet or proof exists here. New source qualification must precede actual preparation. A concrete startup source manifest must fit the unchanged 512-row/8-MiB source bounds, and full preparation must satisfy the unchanged snapshot/evidence budget; neither fit is assumed.

A later installation saved auditor must bind this owner with both old33 and the new installation qualification callbacks, the explicit actual preflight05 audit reference, and the exact completed installation preparation/launcher proofs. It must retain the existing 45 phase controls, 53 Reader/IO controls and real final prefix admission/ready/qualification checks. The immutable preflight-only audit06 is not relabeled as an installation auditor.

No provider code was imported, no tests/builds were run, no output packet was created, and no installation was initiated while drafting this proposal. Read-only source self-review and handoff paths are recorded in `qualification-plan.json`.
