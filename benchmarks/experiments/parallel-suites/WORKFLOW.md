# Changed-source qualification after the fixed runtime screen

Proceed only if the six-pair saved-suite screen passes. Preserve the original
source revision, full filtered test selection and five cumulative production
edits from the existing token/folded/pgrust workflows. Execute cold original,
deliberately wrong, five edited and restored-original states. Original test
source must remain byte-identical. A check-only command accompanies every state.

Compare the retained selector tool with one worker against the new tool with
two workers, using the identical retained exporter/wrapper bytes. Both custom
routes perform strict rustc checking, export and all original assertions in each
measured complete command. Their bytecode and entry catalog must match exactly
for each source state. Use normal OS entropy; never inject the replay shim into
concurrent tests or Cargo. Record every suite, source transition, process, full
command wall time, child CPU, launcher stages and artifact digest.

The primary native control uses two concurrent isolated test processes, each
with libtest threads=1. Also run the retained serial native control, in its own
fresh Cargo cache. This avoids giving the custom runner a concurrency advantage
over its native comparison. Native controls use the repository profile and
the same two Cargo workers as custom routes. Preserve separate per-test child
receipts and collect outcomes in selection order.

Use five fresh independent caches: native parallel, native serial, retained
custom, candidate custom and check. For each source state alternate placement
of the serial native control before/after the existing three-mode balanced
order. Every mode must see a different source digest from its previous command.
Only the five changed-source states enter paired latency medians. Report cold,
wrong and restoration commands separately; no unchanged-build timing claim.

Admission for token is8GiB, raised from the four-cache experiment's6.5GiB to
budget the additional native cache; keep its4GiB child floor. Folded keeps9.5GiB
admission and8GiB child floor; pgrust keeps8.3GiB admission and8GiB child floor.
No external directory is inferred and no resource floor is lowered. Record
available storage before every child. An admission stop is not a benchmark.

Require at least8% median paired complete-command token wall improvement over
the retained custom tool, with at most20% CPU increase. Folded/pgrust allow at
most5% median wall/CPU regression. Report candidate/native parallel ratios,
including whether native remains faster, independently of that retention gate.
Do not change the one-worker default until all guards and source-restoration
controls pass. A passing token result alone permits the separate guards, not
default promotion. Do not rerun failed performance screens for another chance.
