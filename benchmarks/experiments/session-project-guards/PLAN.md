# Prospective project guards for the qualified session runtime

The duration-order candidate has passed the 40-command primary and 110-command
full parser guard. It remains experimental. Before adoption, run fre token, fre
folded, pgrust's smaller control, private rg-aot, then Nushell type relations.
Stop before the next case if a guard fails. No unchanged or noisy timing retry.
The verified fre token replay has passed 192 original test invocations and every
one of 14,892 template hits; its closure is required before the first source run.

For fre and the smaller pgrust control, retain the historical anchor, adopted
baseline and duplicate, ordinary native, native with line tables, and Cargo check.
Replace the former candidate with the qualified session candidate and add a
history-disabled session of the same runtime. This yields eight modes and 176
commands for three original/wrong/five-valid-edit cycles plus final restoration.
All existing production-body edits and original assertions remain unchanged.

Rotate the five custom modes so every mode occupies every custom position across
each cycle's five valid edits. Retain alternating native/native-line placement
outside the custom block and Cargo check last. Explicitly use two Cargo and native
test workers, matching the current shared-host budget. Session workers are two.
Candidate and history-disabled arms use identical normal binaries and options;
only template-history capacity differs. Both retain advisory duration ordering.

Charge complete session kernel CPU, including work before/between/after requests,
plus parent/helper startup and shutdown CPU. Request intervals are charged once;
all remaining session overhead is spread across the 15 valid edits. Add session
startup and shutdown wall costs to those edits. Keep ordinary complete-command
wall/CPU and all-history totals, including original, negative, and restoration.

Retain the earlier project's acceptance rules: token candidate/anchor wall <=0.92,
candidate/adopted wall <1 minus A/A, CPU against both <=1 and worse CPU ratio plus
A/A <=1.05. Folded and pgrust use worse candidate/adopted or candidate/anchor ratio
plus A/A <=1.05 for wall and CPU. A/A is the maximum absolute deviation of each
edit position's three-cycle median duplicate/adopted ratio. Report every pair and
worst individual deviation too. Failed gates with relevant A/A >8% are unmeasurable,
not evidence of regression and not permission to retry.

Before timing, qualify scheduling, original-source transitions, full kernel CPU
conservation, overhead charging, rejection on missing/duplicate/nonfinite records,
history-off attribution, all-cycle inclusion, and all acceptance boundaries.
Require the same closed candidate installation, unchanged adopted compiler tools,
current source bindings, and strict type/borrow rejection before session contact.
Freeze source/controller through closure and independently verify the full result.

The private and Nushell adapters still need implementation against their existing
six-mode controls (no historical anchor), with a seventh history-disabled arm.
Preserve their five edits, outcome/bytecode/catalog checks and 5% regression gates.
The private single-test baseline uses one actual worker; current session protocol
requires two workers, so its idle-worker overhead must be explicit and fully charged.
Do not change the measured runtime to conceal that cost. No expanded thread, OS,
libtest or unwind capability is implied by selected-test-body results.

Use exact fresh namespaces, shared benchmark lock (45s admission), per-command
8GiB floor, public fre14GiB and pgrust10GiB admission. Confirm the added arm's cache
estimate before running; raise admission if existing estimates do not cover it.
Nushell retains its separate ~47GiB estimate, revised upward if the extra namespace
requires it. Only exact closed owned compiler intermediates may be retired. No
peer process control, automatic cleaner repair, new services or purchases.
