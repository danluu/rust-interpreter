# Retired-instruction counter availability

This is a bounded local capability probe after the call-protocol edited-command
measurements. It is not a latency benchmark and does not modify the VM.
Use Xcode's installed CPU Counters template with `xctrace --launch` for one
owned native test process, a five-second recording limit and `--no-prompt`.
Do not attach to existing processes, collect an all-process recording, change
host permissions, elevate privileges or activate any external service.

Launch the exact original exhaustive token test from the terminal, restored
native control of composed-development-edit-anchor-01. Verify the run's raw
record hash and native executable before launch, and preserve original test
output. Hold the shared benchmark lock with45-second admission and require
3 GiB free. Record tool/target hashes, command, child identity and output.
Preserve an unavailable/error outcome; never turn missing counters into zeros.

If recording succeeds, export the table of contents to determine which actual
counter tables/events exist. Counter names, time scope, process attribution
and complete test execution must be verified before any comparison. A useful
follow-up would compare equivalent original native/JIT tests over matching
process scopes, separately recording startup/JIT preparation overhead. Logical
bytecode counts and sampled PCs are not hardware retired instructions. No
performance conclusion follows from this availability probe alone.
