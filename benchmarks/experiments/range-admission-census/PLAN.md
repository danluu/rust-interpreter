# Measure smaller range-guard admission before implementing it

The adopted ordinary region guard requires eight typed accesses to one proven
entry root. Inspect additional groups of four through seven accesses, using the
same proof, span bound, supported operations, work budget and root ordering.
The production entry point keeps its threshold of eight. Only a test entry point
uses four; it never emits or executes the additional guards.

Reconstruct every ordinary and scalar byte of the retained block, exhaustive
and parser native captures. Walk those exact ordinary regions in source order
with separate four-million-unit proof budgets for both thresholds. Require equal
work consumption and identical selected proofs for all previously admitted
groups. Record only newly admitted groups, complete typed sites and disjointness.
Two new controls plus three existing planner controls run in debug and release.

Join exact original operation spans to closed normal-entropy self-PC samples;
two existing ownership controls reject ambiguous or outside PCs. Seven commands,
zero guest executions or executable publications. Scope counts and samples include
work a future guard would retain; they are not guard hit rates, instruction savings
or a speedup estimate. Defer a candidate if additional scope is negligible. If
material, qualify smaller guarded regions against full interpreter memory/fault
and budget oracles before the unchanged complete changed-source token primary.

Use the global benchmark lock and shared ROOT target, two Cargo workers and test
threads, max(14GiB,8GiB+twice target allocation) build admission, and an8GiB child
floor. Retain failed attempts, source pins, exact code evidence and all old gates.
No compiler/Cargo ownership, foreign backend or guest checking policy changes.
