# Native reuse identity census across genuine source edits

Preparation remains a secondary token cost (largest worker about 157 ms of a
4.05 s command), and a larger fraction of the original parser command. Before
building a persistent native cache, inspect saved artifacts from the closed
retained-region-values token primary and indexed-switch parser primary. Use all
eight baseline states in each history, including the deliberately wrong edit
and restoration, with only the five successful edits used in aggregate findings.

A release test-only observer decodes and fully validates each artifact, then
hashes each complete serialized function at its original numeric ID, its full
frame/register/argument/result layout, and the emitter's global target/version/
function-count/heap-mode inputs. Compare exact bodies, then direct callee layouts,
direct callee bodies, and conservatively all transitively called bodies. Keep
indirect calls visible. This is a necessary-condition census, not a complete
cache key or a native-code equality proof. Changes to data contents alone are
reported separately from code identity; no data is reused.

Weight matching function identities with the already closed adopted unprofiled
block-test and parser code maps, requiring an exact body match with each map's
own artifact before assigning bytes. These bytes describe saved code ownership,
not compilation cost, hit rate on a new execution, removable time or speedup.
Report diagnostic read/hash/decode/validation/fingerprinting intervals separately;
they are not a matched end-to-end experiment.

Qualify changed implementations with unchanged interfaces, call-target and
layout/name changes, recursion, global invalidation, independent reachability
oracles and code-map identity rejection. No new guest, machine-code publication,
checking shortcut, cache file format, production policy or compiler-session work.
A future cache would additionally need complete generator/options/proof-state
dependencies, current admission and scalar eligibility, relocation of absolute
calls and assertion identities, validated entries, corruption handling and bounded
storage, followed by strict qualification and a preregistered real-edit primary.

Use the shared lock and existing ROOT target only, two Cargo workers, conservative
build admission max(14 GiB, 8 GiB + twice allocated target), and an 8 GiB child
floor. Bind all source, input, map and terminal evidence; publish a result even
if an expected identity condition has zero scope. No repeated timing screen.
