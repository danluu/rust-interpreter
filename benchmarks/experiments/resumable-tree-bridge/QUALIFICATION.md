12 bridge-specific controls, existing direct/indirect/tree/ABI cases and the
expanded large-register fixture. Speculative tree code has one global quota of
one quarter of the requested code arena (4 MiB at the unchanged 16 MiB default).
Quota failure retains ordinary execution, and no benchmark-specific rule exists.

Install only a new custom VM with the exact adopted exporter/wrapper and a distinct
immutable tool key. Record all setup costs. Validate launcher forwarding and
incompatible-option rejection, then strict/cache/error controls with the new
flag. Exact original real-test profiles must reconcile full logical per-PC
counts, separate tree/backend placement, peaks, values, instructions and entropy.
Measure compilation, extra code, guarded-body closure exclusions and fallbacks.
Operation maps currently reject bridge mode explicitly; do not claim unchanged
body partitions or reuse an ordinary map for its tree code.

Only after correctness and workload placement are established, preregister the
existing 40-command changed-source token primary schedule and gates. Retain the
failed variance-sensitive candidates; do not choose a new noise threshold or
repeat their timings. A passing screen may proceed to the full primary and
held-out projects. No adoption is supported by a fixture or runtime-only result.

Keep two Cargo workers, the shared lock, 16 GiB setup admission and 8 GiB per
child. No subagents, peer interference, AWS activation or goal-state changes.
