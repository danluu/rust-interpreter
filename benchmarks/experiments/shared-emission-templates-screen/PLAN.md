# Shared emission templates: full-parser primary

The primary is conditional on closed workspace, strict-Cargo and actual original
suite sharing qualification. It follows the contract frozen in
../shared-emission-templates/QUALIFICATION.md before candidate timing.

Run32 commands: the original five valid parser edits, original anchor,
deliberately wrong edit and restored anchor, each with ordinary native Cargo,
adopted custom baseline, its independent A/A duplicate and the sharing candidate.
Rotate all four modes. Each mode has a fresh isolated cache namespace and sees
changed source between consecutive commands. Only the five valid edits enter
paired wall/child-CPU ratios; initial build, wrong-source and restoration remain
mandatory correctness controls. Retain all114 original tests, assertions,
artifact-bound entry catalogs and strict type/borrow checking.

Use identical exporter/wrapper binaries, automatic function reuse, cached
toolchain discovery and explicit resumable/persistent/scalar JIT options. The
candidate alone adds --jit-shared-templates. Use two Cargo workers, two custom
suite workers and two native libtest threads. Ordinary OS entropy stays enabled.
All construction, population, locking, copying and report costs remain timed.

Pass only when median paired wall ratio plus its maximum absolute A/A deviation
is below1, paired CPU ratio is at most1 and CPU ratio plus its A/A deviation is
at most1.05. These are engineering gates, not confidence intervals. Record a
failed gate even if noisy; do not rerun this unchanged candidate or start larger
comparisons after failure. A pass still requires full histories and regression
guards on the other projects before any adoption.

Require24GiB free initially, preserving the earlier full-parser reservation
conservatively (8GiB floor plus16GiB for new caches/evidence). Recheck8GiB before
every child. The supervisor and shared benchmark lock retain process ownership;
never disturb peer work. Preserve source backups, exact native executables,
all RBC/catalog identities, command outcomes, resource receipts and terminal
evidence. No performance execution is admitted merely by creating these files.
