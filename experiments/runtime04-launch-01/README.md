# Runtime04 launch draft

Unrun standalone launcher derived from the qualified hash02 launcher. It selects one exact runtime04 phase, reads the prepared packet, requires fresh 24 GiB entry, and observes the detached supervisor through the original terminal-observed timing protocol. Compiler/controller execution is unavailable until an actual prepared launch digest and this reviewed source digest are supplied.

The original runtime04 producer and its 52-test source freeze remain unchanged. The launcher source is retained beside its own raw wrapper output; it is independently pinned rather than inserted into an already prepared input packet. The runtime controller retains the canonical lock, full input checks and unchanged 24/9/8, 14 GiB namespace and 256 MiB evidence limits.

Source-only. No runtime packet exists through this draft, no launch has run, and no performance or runtime qualification follows from it. Observation deadlines never signal a process.

The source-only startup correction keeps the workload environment unchanged and
compares the three explicit launch maps exactly. Before any WORK or process it
replays the actual39 source/raw qualification, loads only its authenticated policy
and owner bytes, and validates the policy-derived relation plus the exact closed
preparation record, launcher, invocation and raw environment observations. The
actual prelaunch time is used only as a stricter chronology upper bound; no
future runtime terminal is synthesized. The later saved-evidence audit still
checks the real runtime start.

Two additional explicit CLI digests are required: `--preparation-sha256` and
`--preparation-launcher-sha256`. Those phase references remain unbound until an
actual preparation has closed and been reviewed. Pure control source/tool
readback introduces no compiler/provider workload. The original operational
launch, finite wrapper wait, detached supervisor observation, capacity checks
and no-signal behavior remain unchanged. Prior source and narrow diff are
retained separately.
