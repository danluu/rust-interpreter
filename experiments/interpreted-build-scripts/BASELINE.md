# Ordinary native baseline controller

`baseline.py` is a controller for the fixture's 28 native Cargo commands. Its
original six pure controls and metadata plan passed on source `8b4422b1`. Native
attempt01 ran one successful Cargo command and all three original fixture tests,
then failed in the controller's old-layout output lookup. Its source restored
successfully. The corrected seven controls and metadata plan02 then passed on
source `d98bdee4`. Native02 qualified the 24 default states and its 25th Cargo
command passed all three tests, then the shared-helper proof failed because the
controller collapsed two same-name `--extern` arguments into one. Sources again
restored. Neither attempt qualifies the complete baseline. The corrected eight
controls, metadata plan03 and fresh native03 below have not run yet.
It does not implement interpreted build scripts or claim a speedup. The exact
three app tests, default profiles/features, libtest concurrency and two Cargo
workers are preserved. Eight uncalled compilation failures and the one wrong
value test failure are required outcomes; the other nineteen commands pass.

Planning records actual installed public `nightly-2026-09-08` rustc/Cargo versions,
executable identities, recursive non-system Mach-O dependencies, library search
results and the full native std inventory. The compiler must report public
revision `cea272fa356e94bd2ee2cadf376630aa0683867a`. System dyld libraries use the
existing explicit uname platform assumption. The Python executable is recorded;
this is not a hermetic operating-system or SDK distribution.

Each native command gets a recorded environment constructed from a small locale,
home and temporary-directory allowlist. Compiler/profile/loader overrides,
interpreter settings and credentials are not inherited. The fresh Cargo home
contains no registry dependencies: the fixture uses only its three local crates.
Discovered ancestor Cargo configuration must be absent. The plan freezes all
28 command argv/environment pairs and the controller, imported helpers, tests,
full fixture and original source bytes. Each stage also copies these exact input
bytes into its owned evidence directory. Run admission requires the reviewed
plan SHA256 and canonical absolute lock with a600-second wait. The existing
supervisor and owned child runner retain process identities and complete raw
streams, with the existing8GiB floor and continuous capacity stop.

The deliberate instrumentation is one transparent `RUSTC_WRAPPER`: this same
frozen script records Cargo's actual final compiler argv, environment and
pre-exec PID, then `exec`s the exact public compiler with unchanged argv, streams
and inherited jobserver FDs. It adds no compiler flags and records no fabricated
post-exec result. Cargo's raw process outcome and artifact records establish
completion. `RUSTC` itself remains the public compiler, including for the
fixture's actual nested `RUSTC --version` invocation. The fixture exposes that
child's successful stdout and marker files but not its PID; the receipt states
that limitation. No timings from this instrumented baseline qualify performance.

Actual Cargo `build-script-executed` messages determine OUT_DIR. Actual
`compiler-artifact` messages and compiler `--extern` arguments determine artifacts;
no search chooses a favorable output. The controller retains raw script output,
directive ordering, stderr, context, generated bytes and history. The unchanged
command and every compilation rejection must leave all recorded script effects
unchanged. Every successful changed history adds exactly one actual history line.
The shared-helper case binds host `--emit=link`, an actual helper `.rlib` extern
and any same-stem `.rmeta` companion from the same Cargo artifact record,
the native proc-macro `.dylib`, and the application's executed unchanged macro
assertion through the helper3→5→3 history. This does not claim a non-inlined helper
call: native linkage may use its MIR. Cargo artifacts and generated outputs are
copied before the next edit. All original fixture bytes are restored with the
existing staged-restoration helper, including on a failed command or check.

The narrow correction follows exact pinned Cargo `3c0b5347` source:
`compiler/layout.rs:493–498` puts build-script execution files in the unit's
`run` directory; `compiler/custom_build.rs:1461–1468` names them `stdout`,
`stderr`, and `root-output`; line688 writes the exact OUT_DIR path bytes into
`root-output`. `workspace/features.rs:844,1595` enables this layout by default;
its temporary opt-out is absent from the sanitized environment. The controller
derives that single same-unit directory from Cargo's actual OUT_DIR and verifies
the recorded root bytes before reading or retaining outputs. It never searches
for a passing alternative or falls back to the old layout. The new control
rejects another OUT_DIR, a missing stdout despite an old-layout decoy, and a
symlinked output file.

After source review, the eight pure controls may run under the canonical supervisor:

```text
python3 -B -m unittest discover -s tests -p test_interpreted_build_scripts_baseline.py -v
```

Only after those controls and source review, materialize the native plan:

```text
python3 -B scripts/supervise_experiment.py --run-id interpreted-build-scripts-plan-supervisor-03 -- python3 -B experiments/interpreted-build-scripts/baseline.py plan --plan <owned-worktree>/experiments/interpreted-build-scripts/planned-native-03.json
```

Then review the actual identities and the full plan SHA before admitting:

```text
python3 -B scripts/supervise_experiment.py --run-id interpreted-build-scripts-native-supervisor-03 -- python3 -B experiments/interpreted-build-scripts/baseline.py run --plan <owned-worktree>/experiments/interpreted-build-scripts/planned-native-03.json --plan-sha256 <reviewed-sha256>
```

Plan and run destinations are fresh and fixed. Failures remain intact; a reviewed
fresh attempt requires an explicit source/plan update, never reuse or overwrite of
the failed destination. No application, held-out benchmark or compiler source is
part of this baseline.
