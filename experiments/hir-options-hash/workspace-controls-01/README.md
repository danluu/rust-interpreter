# Six offline workspace controls

Source preparation only until a concrete freeze is reviewed. This packet copies
the root's reviewed `generated-workspace-isolation/controls.py` byte for byte.
It executes six Cargo metadata callbacks in a fresh sibling fixture, preserving
both expected workspace errors and four exact successful membership results.
No compiler build, network command, application change, or deletion is included.

`prepare.py` reconciles the three actual failed build01 children and preserves
that failure. The actual extracted D2 Cargo, rustc and library bytes must match
the admitted archive members. Pure current-byte Mach-O parsing must reproduce
both already qualified closure identities after the exact old-to-new source
path remap; no new otool or loader process is smuggled into the six calls.
All other extracted stage0 files and source/SDK inputs remain bound as well.

`run.py` holds the canonical lock for a bounded 600-second admission, requires
16 GiB on entry, and checks full inherited metadata source/provider identities
before and after. It checks all recorded stamps and provider search states
around every child. The metadata fixture must remain below 4 MiB and evidence
below 256 MiB. The copied bounded helper preserves the existing 9 GiB active
stop and 8 GiB floor policy, exact owned-process checks and exception monitoring.
Its only process changes are fixed fixture cwd routes and inherited canonical
descriptor; it does not gain authority over any other process.

The outer X manifest is frozen unchanged for these controls. A passing fixture
does not itself change that manifest, retry bootstrap, qualify a compiler build,
or produce a performance result. Every failure is retained without automatic
retry. X owns launch execution after root review; the preparer has no subprocess
or compiler-execution path.
