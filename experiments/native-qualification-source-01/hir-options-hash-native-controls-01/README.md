# Native compiler role and behavior controls

Source-only implementation, pending actual qualified B3 composition. No native
plan, freeze, discovery invocation or workload has run. `prepare.py` requires an
actual passed B3 receipt and its independent audit, then derives the native20
recipe from the actual D2/E2 version observations, B3 output inventory, ordered
private driver pair and E2 loader closure. It does not probe a compiler or infer
future output hashes. Read-only preparation and the resulting workload both
need their own exact review before execution.

The native history keeps the original18 compile/run/error/restoration commands
and adds two explicit attempts to use B3 as an application sysroot. The latter
must report metadata incompatibility naming actual B3 standard-library files.
No hash-driver process, run-make recipe or application benchmark is included.

Discovery inherits every B3 frozen input, route and absence guard, binds actual
B3 output bytes, reads back all19 actual precursor commands, and freezes the
new source/proof closure. Runtime admission repeats the exact B3 audit binding
and complete provider/inventory checks. The existing offline distribution URL
`RUSTUP_DIST_SERVER=file:///dev/null` is retained; every other ambient RUST*,
DYLD*, LD* or encoded compiler-flag override is rejected. The recipe sets its
explicit RUSTC_BOOTSTRAP and loader-observation values only per command.

The exact A-path shared monitor is mandatory because its source location binds
all four evidence owners. Admission uses24GiB entry,9GiB stop/8GiB floor,
14GiB candidate namespace and256MiB aggregate evidence across all completed
compiler failures/continuations, B3, native, run-make and hash stages. The native
stage creates a fresh TMPDIR and fresh native-controls fixture root. It cannot
signal an unrelated process, and uses the shared exact ownership checks for
its own children.

The14 parser controls and16 shared-monitor controls are already independently
qualified; that source evidence does not qualify the future native integration.
`observations.py` and `test_observations.py` remain unchanged. Future actual
native success requires20 recorded command receipts, four retained executed
binaries, exact compiler error parity and HIR event observations, unchanged
source restoration, actual static and runtime loader observations, and a
separate independent audit with status `verified`, receipt_sha256 and
result_sha256 for the hash-driver stage.

The unfrozen native draft adopts the qualified shared compressed-snapshot helper after B308. Exact selected logical source/proof bytes, including the native freeze, receive deterministic measurement and full gzip/hash readback. The separate launch-bound projection is retained verbatim. Logical parsing remains bounded at 512 MiB/64 MiB per file; actual compressed evidence and all prior stages remain under the unchanged aggregate 256 MiB, with explicit 32 MiB later-stage allowance and document/block reservation. Neither discovery nor native execution has run.
