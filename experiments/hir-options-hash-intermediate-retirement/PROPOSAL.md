# Completed compiler intermediate retirement proposal

This is an unrun proposal. It contains no deletion controller, frozen launch or
authorization to remove a file. The existing 24 GiB workload entry, 9 GiB stop,
8 GiB floor, 14 GiB aggregate compiler namespace and 256 MiB aggregate evidence
limits remain unchanged.

The completed native compiler and interface suite left 6,098,382,848 observed
allocated bytes in `N/source/build/aarch64-apple-darwin/stage1-rustc`. The selected
scope is exactly the 4,646 ordinary single-link files named by the retained
eligibility report, comprising:

| Kind | Files | Observed allocated bytes |
| --- | ---: | ---: |
| `*.rcgu.o` | 3,954 | 2,445,393,920 |
| Unstamped `.rlib` | 391 | 2,516,762,624 |
| Unstamped `.rmeta` | 301 | 393,347,072 |
| Total | 4,646 | 5,355,503,616 |

Every candidate has a retained full content hash and complete inode identity.
The content assessment read 5,346,045,319 logical bytes and rechecked identities
after hashing. A separate association record binds every candidate to retained
successful native producer commands by exact output directory and compiler
crate/extra-filename stem. The first conservative association omitted the extra
filename from object stems; that original report remains retained. The second
association applies the bound `OutputFilenames` source rule and resolves all
4,646 names without rerunning any compiler or changing any output.

The 588 recorded producer rows belong to the original 16 successful build02
children and the first six successful continuation01 children. The failed
support route, both failed controller terminals and all raw streams remain
unchanged. These commands, source/tool identity records and full old cache
hashes provide reconstruction references. They do not promise a byte-identical
rebuild. Cache bytes need not be copied into an archive merely because they were
generated; qualification artifacts and provider bytes remain protected.

The filter excludes every current `.librustc-stamp` entry and every hardlinked
candidate inode, including aliases wholly inside the tree. The complete stamp
has 256 entries, all preserved. Current E2/D2, CI LLVM, stage0-sysroot, installed
R tools, bootstrap shims, all dep-info, Cargo fingerprints, final test
executables, source and registry contents are outside the removal list. Nine
relevant immutable input catalogs, including X's 100,344-file metadata catalog
and 782-file continuation catalog, contain no direct candidate file binding.
The proposal preserves those catalogs as historical records and does not alter
their assertions to conceal a removed path.

Consumer review establishes the following scope:

- B3 producer04 hashes only private stamp members. It parses competing unstamped
  output names from retained raw argv without opening their current files. The
  native compiler's ordered driver dylib/rmeta pair is in the preserved stamp.
- Native qualification uses B3 copies and qualified E2/D2 loader closures.
  The hash driver uses those providers, its source/fixtures, SDK/clang and
  retained prerequisite catalogs. Neither has an unstamped cache consumer.
- The proposed support successor uses the registered D2 `ToolBootstrap` test
  route and the separate `bootstrap-tools` directory. It must not rebuild or
  retest the already completed native compiler/interface suite. X will bind the
  exact successor source before a retirement execution packet is frozen.
- The direct run-make stage uses D2, its support artifacts, E2 and a fresh recipe
  directory. Its preparation remains blocked on actual support qualification.

Of the proposed files, 1,690 occur in continuation01's initial mutable-output
snapshot and 143 are referenced by `.check-librustc-stamp`. Retirement must
explicitly list those transitions. The old check stamp would then describe an
incomplete check cache and must not be represented as a currently complete
artifact set. Its original bytes stay as evidence. A future checked compiler
build would need to reconstruct the retired cache; no such build is part of
the proposed support continuation. New preparation must inventory the actual
post-transition tree while retaining the old observations and transition proof.

Before any removal proposal can become an executable packet, it must retain
the complete hashes, inventories, source/tool/actual-command references,
consumer contracts and failed histories outside N; revalidate the exact
candidate membership and single-link identities; verify all protected providers
and stamp members; and obtain empty read-only open-handle/mapping probes for the
exact target subtree. Canonical admission remains bounded to 600 seconds with
9 GiB live free-space checks. Point-in-time quiescence is not a reservation and
authorizes no process signaling.

A future narrowly reviewed remover would open the exact root and parent
directories with nofollow FDs, revalidate identities immediately before each
`unlink(..., dir_fd=parent)`, retain a per-file deletion ledger and stop on any
changed precondition. It would remove only the explicit file list, keep all
directories and noncandidate files, record affected directory bookkeeping, and
recheck protected providers and remaining membership afterward. A partial
failure would remain a partial transition, with no automatic retry.

The allocation total deduplicates inodes, not APFS shared extents. It is not a
promise that 5,355,503,616 bytes will become free. Actual free space after any
retirement, including retention overhead and unrelated host allocation, decides
whether a later 24 GiB admission is possible. This is a resource admission task,
not a build-performance result or benchmark shortcut.

Two separate optional scopes are already assessed but are not included here:

- The remaining original, already incomplete Oxc native01 toolchain: 150
  ordinary files, 320,610,304 observed allocated bytes, all previously matched
  to independent qualified composed copies. This would finish retirement of an
  old installation, not delete a cache. It requires its own current consumers,
  retained inventory and quiescence review.
- The completed exporter target: 111,529,984 observed allocated bytes. Installed
  exporter/wrapper copies have independent inodes and matching bytes, but the
  target's complete preservation, installed-reader source-path semantics and
  quiescence review are not complete. It is not currently eligible for removal.

These optional estimates provide little margin and may still leave admission
blocked. Historical evidence snapshots and every other cache/provider remain
out of scope. `proposal.json` binds the exact assessment records without
asserting that a future retirement has happened.
