# Runtime04 saved-evidence audit draft

This is source-only work. There is no runnable audit entry point, qualified
fixture result, prepared runtime packet, or completed runtime qualification in
this directory. Original audit03 sources and runtime03 producer/test sources
remain unchanged.

The runtime04 producer belongs to the exporter worktree. Its hash predecessor
is ROOT `hir-options-hash-driver-stage-03` / `.work/hir-options-hash-driver-02`.
Its first-preflight and installation packets use `preflight-plan-01` and
`installation-plan-01`; actual WORK and supervisor namespaces end in `04`.
No future hash or runtime audit digest is filled in by this source draft.

`reader.py` currently preserves the parked03 callback predicates, changing only
the runtime namespace to04. It is not an orchestration entry point. Before
these predicates can publish an audit, a reviewed runner must perform the
following ordered work:

1. Authenticate the exact reviewed audit sources and actual fixture proof.
   Bind the future exact packet, terminal, outer closure and explicit launcher
   record using digests supplied only after those records exist. Read through
   bounded no-follow callbacks, retain full current identities and final
   rechecks, and preserve unavailable contemporaneous observations.
2. Bind the actual successful hash02 terminal, result and independent audit.
   Check the raw compact plan/input digests before any helper import. Qualify
   actual70, authenticate `plan_reference.py`, then reconstruct only the exact
   hash plan route through runtime04 `Reader.read_hash_plan()`. Keep raw wire
   hashes distinct from the expanded typed plan. Qualify the file-table29
   reader and reconstruct the complete native03 base plus disjoint delta;
   retain every original selected snapshot input and all nonfile metadata.
3. Run the complete authenticated runtime04 prerequisite Reader once with
   full checks. Rebuild its prior through `stage.continued_catalog`: qualified
   beta/native history plus independently audited failed hash01. Then extend
   the actual successful hash02 owner with the nonrecursive `snapshot_owner`
   callback. Only the exact hash plan route is expanded for catalog reads;
   its `file_record` always authenticates physical raw bytes. During final
   installation, add the independently audited actual preflight owner.
4. Authenticate the actual v2 snapshot qualification and run
   `verify_reference` on every physical catalog row, including unselected
   rows. Recheck the new runtime logical selection, own compact input bytes,
   full gzip EOF/hash and stable aliases, exact new directory membership,
   total versus new allocation and unchanged 256MiB aggregate reservation.
5. Reconstruct the complete actual recipe independently with this directory's
   `recipe.py`, and compare it to the frozen plan and every saved child/raw
   record. The inherited environment must prove absent `RUSTC`, `RUSTDOC`,
   version/sysroot and dynamic-loader overrides. Preserve every other key.
   Authenticate provider/sysroot/executable routes through the full frozen
   input guard. No constructor, path resolution or compiler probe occurs in
   pure recipe reconstruction.
6. Validate the phase-specific output, perform full final input/output
   membership and stable-identity checks, and only then publish an exclusive
   `status: verified` audit with actual receipt and result digests. The audit
   result is WORK `source-probe/result.json`, not an invented WORK/result.json
   or an invented terminal field.

`preflight.py` independently validates the first two actual E0080 records,
their local/remapped source observations, exact retained fresh source copies,
and the candidate-only scope. It must not call `preflight_history.validate`:
that helper correctly requires an already existing independent audit and is
appropriate only for the later installation. The first audit has no circular
qualification dependency.

`final_runtime.py` derives `len(spec.loader)+5` actual children, the final key
and sysroot, complete immutable payload inventory, fresh copied inodes,
`ready.json`, `admission.json`, and both copies of the source qualification.
It reparses the actual loader/version/sysroot/options observations and final
two E0080 records. It does not call an installer, compiler constructor or
final-validator factory. It does not require historical hardcoded file counts
or nonexistent ready/qualification fields in the terminal.

`test_recipe.py` contains thirteen tiny in-memory recipe tests, including
poisoned constructor/workload APIs. They are unrun. Their fake `/fixture`
paths are never opened; their fake policy callbacks do not qualify actual
provider bytes or diagnostic rendering. Full phase fixtures, exact runtime04
source integration and the bounded actual audit runner remain to be written
and independently reviewed before any execution.
