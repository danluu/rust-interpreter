This unrun adapter prepares standard-library metadata only after runtime07 has
passed its independent installation audit. The plan is deliberately unbound:
runtime key, ready/admission/qualification and audit hashes, current environment,
configuration, executors and source sizes are not yet actual evidence. No
inputs.json or workload output has been created by this source task.

prepare.py derives from R/experiments/runtime-compiler-installation/std-01 and
retains its source/configuration/executor checks, input retention, process
supervision and complete seven-command readback. imports.py selects the original
R modules with one explicit substitution: runtime_compiler is the reviewed
native-loader-probes-01 module. Both the supervisor and std_cli.py use this
selection. The original std_mir_source_paths.py is loaded at its real path, so
its ROOT remains R. Its main(), Cargo recipe, source copies, key derivation,
diagnostics, readiness validation and lock behavior remain unchanged.

The selected aliases stay installed for the complete ordinary CLI call,
including its lazy runtime/custom-Cargo/diagnostic imports, and are restored on
return or exception. There is no module __file__ or ROOT rewriting. The factory
authenticates the complete ten-file selected import closure before loading any
target module. selection.json also preserves the original finite 108-script
source scope; future inputs.json must contain and authenticate these current
files, all adapter sources, plan, descriptor and complete selected proof and
executor files. The ten import files do not replace that broader source freeze.

The ordinary CLI owns canonical then std-mir locks, each with the original
600-second wait. Its supervisor does not acquire a conflicting canonical lock.
The resource policy stays 16 GiB entry, 9 GiB active stop and 8 GiB floor, with
32 MiB per retained input and 64 MiB total. The offline/locked Cargo metadata
build keeps two jobs and the original flags. Exact direct child labels/codes
remain cargo-location/0, cargo-version/0, cargo-library-1/0, cargo-library-2/0,
probe-native/1, metadata/0 and probe-prepared/1. Cargo's compiler descendants
remain ordinary work; seven is not a claim about all operating-system children.

Future binding consumes the actual runtime07 receipt and audit12 report,
matching its phase_result runtime key, sysroot and three publication hashes.
The selected runtime loader performs its unchanged readiness, identity,
loader-policy and immutable-stamp checks. The adapter does not replay or invent
another installation proof tree. The std key is derived by the ordinary CLI
after actual Cargo, environment and configuration checks. A historical std key,
old CF environment value or old standard-source size is never relabeled current.

The command's sole typed source_freeze_sha256 placeholder expands only after the
external inputs.json hash is known. The plan itself is in that freeze and thus
cannot contain that hash literally. All other ordinary CLI arguments are exact.

test_adapter.py contains twelve unrun pure tests for checked module loading, alias
and argument restoration, unchanged original module path/root, rejection and
typed placeholder handling and the actual admission wrapper schema. They use owned temporary fixture modules only;
they do not import any R/provider module or run a compiler/std command. Proposed
development command, pending source review:

    /opt/homebrew/bin/python3 -B /Users/danluu/dev/rust-interp-semantic-reuse-20260913/experiments/runtime-std-after-installation07-01/test_adapter.py -v

Run that command from R. It is selection testing, not runtime or std
qualification. Actual std preparation remains gated on audited installation07,
bound current sources/configuration/executors/environment and a reviewed launch.
All original source/history files and failed attempts remain untouched.
