# Experimental stable incremental CGU grouping

This is an owned local compiler experiment for rust-interp. It is not an upstream Rust contribution. The base compiler is `cea272fa356e94bd2ee2cadf376630aa0683867a`; the stock installed compiler and interpreter launcher are unchanged. No performance result is claimed here.

The opt-in tracked option `-Zstable-cgu-partitioning` changes only the merging step after ordinary mono-item placement and before ordinary symbol internalization. For incremental, non-coverage builds with more initial groups than the configured codegen-unit count, it hashes each initial group name into a fixed number of buckets. Bucket names include the crate identity, algorithm version, configured count and bucket index. Complete item maps are combined in initial-group name order. Duplicate entries must be identical local copies. Empty buckets are retained so the configured count is not silently reduced.

Normal collection, target checks, inline-copy placement, linkage, symbol internalization, duplicate-symbol detection, metadata encoding, checking and codegen dependency validation still run. Stable names do not authorize object reuse: rustc still requires the prior work product and an ordinary green codegen dependency node. Coverage, nonincremental and already-small group sets follow the stock path.

The intended opportunity is reduced repartitioning after body-size changes. Fixed buckets can be imbalanced, duplicate more inline bodies, and emit empty object files. Crossing the initial-group-count threshold can repartition the crate. All these costs must be included in later comparisons. Module and generic additions can legitimately change affected bucket contents. There is no source, crate-name, edit-pattern or benchmark-specific branch.

`bootstrap.toml` uses a downloaded LLVM development package for the exact base revision, bootstrap-managed CI LLVM, the ordinary pinned beta bootstrap compiler, optimized Rust code and enabled compiler debug/overflow assertions. The matching downloaded compiler-rt provides coverage runtime sources. LLVM submodules remain disabled and no LLVM source checkout is present; unavailable CI LLVM must fail setup. The final configuration explicitly sets `omit-git-hash = false` to retain the real source commit identity. Stage 1 provided the first native correctness gate; the complete stage2 package is now qualified for the subsequent interpreter integration.

`run-owned.py` records source hashes, config hash, selected environment, command, owned process identity, logs, resource usage and disk samples while holding the shared benchmark lock. It requires an estimated stage budget plus 8GiB free before admission. Setup admission normally waits up to 45 seconds; an explicit bounded option allows 600 seconds using a queued flock while the supervisor remains observable. Composition and native qualification also allow an explicitly requested 1800-second queue during longer shared workloads. This changes only setup waiting, never a measured build clock or compiler option. Build and setup costs are separate from warm edited-build measurements. Any performance comparison must use the same custom compiler with the option off and on, matching the entire Cargo/source/history/settings/environment and including host work plus execution validation.

The focused Rust tests are the option-hash test, `tests/codegen-units/partitioning/stable-merging.rs`, and `tests/run-make/stable-cgu-partitioning/rmake.rs`. The tracked-option unit test, all 14 partitioning tests and the run-make history passed with the final stage2 configuration. All 59 runtime and native-standard-library files remained byte-identical between the completed stage2 build and final tests; the test setup added only rustdoc. Preliminary stage1 tests also passed and are retained separately. The run-make history checks grouping and reuse across body-size edits, added/removed modules, option transitions, explicit counts and empty buckets, with native generic/inline/static/thread-local execution and stock coverage/unmerged fallbacks. A same-width source edit isolates grouping from unrelated source-span movement in this correctness fixture; it is not a timing benchmark or an acceptance measurement.

`package-owned.py` composes the stage2 runtime with bootstrap's own `rustc-dev` and `rust-std` component images and the unchanged pinned `rust-src` component. Exact input paths and file digests must match inventories captured when the successful bootstrap commands finish. Every qualified runtime file, including the native LLVM alias, must survive with identical bytes; standard and private component overlays reject conflicting files. Bootstrap's live compiler-source link is omitted in favor of materialized sources from the verified compiler development image. The original source comparison checks 2,305 library files and 79 backtrace files; only the normal distribution exclusions are absent. This avoids full upstream distribution steps that vendor unrelated tool workspaces. The completed prefix is an input to the repository's separate immutable compiler installer, which validates loader closure and publishes the final identity. The final package preserves all 60 qualified runtime paths and passed 15 native binary states with all 6,982 packaged files unchanged. Exact build, test and packaging receipts are in [the compiler evidence](../../results/stable-cgu-compiler-01/README.md); immutable installation and interpreter qualification are separate gates.

`native-entry-controls.py` adds native binary entrypoint coverage at the changed merge seam: 65 reachable modules, CGU counts 1/4/64, ordinary unequal-width edits, restoration and option transitions, with static, thread-local and generic values executed in each state. It requires stable bucket names when enabled and empty buckets at count 64. It uses two backend jobs as a correctness resource limit. Its timing is not a performance measurement.

The current assertions-enabled compiler is for correctness and a same-binary off/on mechanism comparison. [The separate production plan](PRODUCTION-PLAN.md) explicitly records compiler/tool/native-std assertion policy, separate identities and repeated qualification before an eventual production-profile absolute-target assessment. No production build has started.
